# Operate and Read surfaces (app UI, dashboards, tools, docs)

Familiarity is a feature here. The test: a user who knows the category trusts the interface at once and does not pause at a strange component. (S3 operate; UX law 3, Jakob)

## Winning rules
- **Do not deal a new direction (C1).** The taste direction draw is for Persuade and Experience. Operate and Read follow convention, the project's design system, and `../../taste/references/app-screens.md`.
- **Type:** one well-tuned family. Fixed rem scale, ratio about 1.125-1.2. Prose lines 65-75 characters. Dense tables may run wider. (S3 operate)
- **Colour:** restrained. Accent for primary action, selection, and state only. Standard state vocabulary. (S3 operate)
- **Borders:** quiet borders are normal in app screens. Gradients, glows, icons in tinted squares, rainbow charts, and invented vanity numbers are not. (taste app-screens, C11)
- **No fake dashboards** made of grey bars. Charts show real data that adds up, with one finding stated. (taste)
- **Failure mode is strangeness without purpose:** over-decorated buttons, mismatched controls, gratuitous motion, display fonts on labels, invented affordances for standard tasks. Avoid all. (S3 operate)
- **Few choices per screen.** One primary action per section. Recommend a default. Reveal advanced options on demand. (UX laws 1, 7, 13, 19)
- **Status is visible** with a text label (C9). Tabular figures in tables.
- **Read surfaces** (docs, articles, help): structure for comprehension first, then make reading worth staying in. (S3 mode-read)
- **Review components** with `../../craft/reference/component-review.md` when shipping a design-system component.
